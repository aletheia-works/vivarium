# Security Policy

## Supported versions

Security fixes go to the `main` branch, the website built from it, and the
next release of the [MCP server](packages/mcp-server/). Update to the latest
release to receive them.

## Reporting a vulnerability

Please [report vulnerabilities privately](https://github.com/aletheia-works/vivarium/security/advisories/new)
through GitHub, not in a public issue. Examples:

- Code from a reproduction escaping the browser or container it runs in
- Unauthorized access to a live preview
- Credentials exposed by a workflow
- A compromised dependency or published package

Include the steps that reproduce the problem and what an attacker could do
with it. Reports without a reproduction may be closed, including reports
written with AI tools.

For suggestions that are not exploitable, such as tightening a workflow's
permissions, open a normal
[issue](https://github.com/aletheia-works/vivarium/issues/new/choose).

## What to expect

Vivarium is an open-source project without a service-level agreement. We
respond on a best-effort basis and agree on the disclosure timing with you
before publishing an advisory. There is no bug-bounty programme.
