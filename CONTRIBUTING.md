# Contributing to Vivarium

Thanks for helping. Bug reports, new reproductions and documentation fixes are
all welcome. For an open-ended question, start a
[discussion](https://github.com/aletheia-works/vivarium/discussions).

## Set up

Install [mise](https://mise.jdx.dev), then install the pinned tools:

```bash
git clone https://github.com/aletheia-works/vivarium.git
cd vivarium
mise install
```

Run the website locally on port 3000:

```bash
mise run docs:dev
```

## Repository layout

| Path | Contents |
|---|---|
| `src/layer1_wasm/` | Reproductions that run in the browser |
| `src/layer2_docker/` | Reproductions that run in Docker |
| `src/layer3_previews/` | Live previews of pull requests |
| `packages/mcp-server/` | The published MCP server |
| `docs/` | The website; pages are in `docs/site/en/` and `docs/site/ja/` |
| `tools/` | Tools only CI runs |
| `infra/` | GitHub settings and preview infrastructure, as OpenTofu |

## Add a reproduction

Each layer's README explains its conventions:

- [Layer 1](src/layer1_wasm/README.md): copy the closest existing recipe. You
  edit `recipe.json`, `page.en.html` and `i18n.ja.json`; `index.html` is
  generated by `mise run repro:pages`.
- [Layer 2](src/layer2_docker/README.md): start from `mise run recipes:new` and
  check the result with `mise run recipes:verify`.
- [Layer 3](src/layer3_previews/README.md): previews are written by hand and
  need infrastructure access, so talk to the maintainers first.

## Publish your own copy

To publish your recipes from a fork, add the repository variable
`VIVARIUM_FORK_DEPLOY` with the value `true`. The `deploy-docs` workflow then
deploys the site to your fork's GitHub Pages on the next push to `main`. Layer 2
images and verdict snapshots are published only from this repository.

## Before you open a pull request

Run the quick checks for what you changed:

| Changed | Run |
|---|---|
| Anything | `mise run lint:all` |
| Website | `mise run ci:docs-unit` and `mise run ci:docs` |
| A Layer 1 recipe | `mise run repro:typecheck` and the recipe's `bun test` |
| MCP server | `mise run ci:mcp` |
| Fixed-guest builder | `mise run ci:fixed-guest-builder` |
| Layer 3 previews | `mise run ci:previews` |

You do not need to run the Playwright suites locally. They take a long time,
and CI runs them on every browser.

## Pull requests

- Write the title and commits as
  [Conventional Commits](https://www.conventionalcommits.org), starting the
  subject with a lowercase letter: `fix(mcp): handle an unknown slug`.
- Keep each pull request to one change.
- When a website page exists in both languages, update both.
- If an AI tool wrote the change, name the tool and model on the last line of
  the description.
