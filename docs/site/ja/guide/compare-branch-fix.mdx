<Page>
  <PageHero
    eyebrow="// GUIDE · 修正の検証"
    title="修正で本当にバグが消えるかを確かめる。"
    sub="修正を入れた状態で同じ再現を実行し、判定を比べます。正しそうに見えるだけの変更では結果は変わりません。"
  />

  <Section
    eyebrow="// 1 · 結果を読む"
    heading="効いている修正は判定を変えます。"
  >
    <ul>
      <li><strong><code>reproduced</code> → <code>unreproduced</code>:</strong> 修正でバグが消えました。</li>
      <li><strong><code>reproduced</code> → <code>reproduced</code>:</strong> 修正で結果は変わりませんでした。</li>
      <li><strong><code>unreproduced</code> → <code>reproduced</code>:</strong> 変更でバグが入りました。</li>
      <li><strong><code>unreproduced</code> → <code>unreproduced</code>:</strong> もともとバグが起きていないので、この実行から修正については分かりません。</li>
    </ul>
    <p>Layer 2 で 0 と 1 以外の終了コードで終わった実行は、判定を出さずに止まります。ただし、失敗して 1 で終わるスクリプトは <code>unreproduced</code> になり、効いている修正と同じ判定に見えます。判定だけでなく出力も確認してください。</p>
  </Section>

  <Section
    eyebrow="// 2 · LAYER 2"
    heading="修正入りのイメージをビルドして比べる。"
  >
    <NumberedList
      items={[
        {
          lead: 'イメージをビルドして push する。',
          body: <>フォークに修正を入れ、レシピの <code>Dockerfile</code> でビルドして、公開レジストリに push します。ワークフローは認証なしでイメージを取得します。</>,
        },
        {
          lead: 'ワークフローを実行する。',
          body: <><code>gh workflow run branch-fix-verdict.yml --repo aletheia-works/vivarium -f slug=&lt;slug&gt; -f branch_image=&lt;your-image&gt;</code> を実行します。リポジトリへの書き込み権限が必要です。権限がない場合は、自分のフォークで Actions を有効にして <code>--repo &lt;you&gt;/vivarium</code> を指定します。</>,
        },
        {
          lead: 'アーティファクトをダウンロードする。',
          body: <>実行すると <code>branch-fix-verdict-&lt;slug&gt;-&lt;run_id&gt;</code> という zip がアップロードされます。</>,
        },
        {
          lead: '比べる。',
          body: <>zip を<a href="/vivarium/ja/repro/compare">比較ページ</a>にドロップします。2つの判定が並んで表示されます。処理はすべてブラウザ内で行われます。</>,
        },
      ]}
    />
    <p>自分の CI からビルドを確かめる場合は、<a href="/vivarium/ja/guide/integrate-with-your-repo">CI で使う</a>を参照してください。</p>
    <Callout>
      AI エージェントからは、<code>verify_branch_fix</code> が Layer 2 のレシピについて、このワークフローのコマンドと比較ページのリンクを返します。
    </Callout>
  </Section>

  <Section
    eyebrow="// 3 · LAYER 1"
    heading="リリース版と修正を並べて動かすページがあります。"
  >
    <p>Layer 1 のレシピの一部は修正を2つ目のペインに表示するので、1つのページで2つの出力を比べられます。</p>
    <ul>
      <li><a href="/vivarium/ja/repro/dateutil/1478/">dateutil #1478</a></li>
      <li><a href="/vivarium/ja/repro/lark/1585/">lark #1585</a></li>
      <li><a href="/vivarium/ja/repro/jj/10189/">jj #10189</a></li>
    </ul>
    <p>Python のレシピに修正を追加するには、フォークとブランチを指定した <code>fix-candidate.json</code> を含む PR を送ります。MCP ツールの <code>prepare_fix_candidate</code> で作成できます。<a href="/vivarium/ja/guide/use-from-ai-agent">AI エージェントから使う</a>を参照してください。</p>
  </Section>

  <Section
    eyebrow="// 4 · LAYER 3"
    heading="プレビューに比較はありません。"
  >
    <p>ライブプレビューはプルリクエストのアプリケーションを表示するもので、そのプルリクエスト自体が修正です。レビュアーはアプリケーションを使って確認するので、比べる判定はありません。</p>
  </Section>
</Page>
