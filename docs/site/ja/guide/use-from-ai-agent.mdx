  <Section
    eyebrow="// 3 · ツール"
    heading="サーバが提供するもの。"
  >
    <h3>再現を探す・読む</h3>
    <ul>
      <li><strong><code>list_recipes(layer?, project?, q?)</code></strong>: 再現を一覧にします。レイヤー(1、2、3)、プロジェクト、slug・プロジェクト・タイトル内の文字列で絞り込めます。</li>
      <li><strong><code>get_recipe(slug)</code></strong>: 1つの再現の詳細とリンクを返します。</li>
      <li><strong><code>lookup_verdict(slug)</code></strong>: Layer 2 は保存済みの判定結果を、Layer 1 は開くべきページを(判定はブラウザで行われるため)、Layer 3 はプレビューのリンクを返します。</li>
      <li><strong><code>match_error(text, limit?)</code></strong>: エラーメッセージやスタックトレースに近い再現を順位付けします。トークンの一致、同義語、小さな入力ミスの許容を使います。順位は<a href="/vivarium/ja/repro/match">エラー検索</a>のページと同じです。LLM は使いません。</li>
      <li><strong><code>search_upstream_issues(project?, repo?, query?, ...)</code></strong>: プロジェクトの GitHub Issue から、再現する価値のあるバグを探します。認証済みの <a href="https://cli.github.com"><code>gh</code></a> が必要です。</li>
    </ul>

    <h3>修正を検証する</h3>
    <ul>
      <li><strong><code>verify_branch_fix(slug, fix_url?, fix_source?)</code></strong>: Layer 2 では、ワークフローのコマンドと比較ページのリンクを返します。ワークフローの実行には Vivarium リポジトリへの書き込み権限が必要です。他のレイヤーでは今のところエラーを返します。詳しくは<a href="/vivarium/ja/guide/compare-branch-fix">修正の検証</a>を参照してください。</li>
      <li><strong><code>verify_and_report_fix(slug, ...)</code></strong>: 検証の次の手順を判断し、<code>auto_execute</code> が <code>false</code> でなければ実行します。Vivarium のチェックアウトと <code>gh</code> が必要です。</li>
      <li><strong><code>create_fork_pr(slug, current_state, pr_title, ...)</code></strong>: push 済みのフォークのブランチからドラフトの PR を開きます。既定では <code>dry_run</code> によりコマンドを返すだけです。実際に開くには <code>gh</code> が必要です。</li>
    </ul>

    <h3>カタログに追加する</h3>
    <ul>
      <li><strong><code>prepare_new_recipe(project, issue, title, ...)</code></strong>: 新しい再現に必要なコマンドとファイルを返します。</li>
      <li><strong><code>prepare_fix_candidate(slug, fork_url, branch, ...)</code></strong>: Layer 1 のページで、フォークの修正をリリース版と並べて動かすためのファイルとコマンドを返します。</li>
    </ul>
  </Section>

  <Section
    eyebrow="// 4 · 困ったとき"
    heading="うまくいかない場合。"
  >
    <ul>
      <li><strong>新しい再現が見つからない。</strong> サーバはカタログを5分間キャッシュし、オフラインでは同梱のコピーを使います。サーバを再起動すると取得し直します。</li>
      <li><strong>Layer 1 の判定結果が返ってこない。</strong> 正常な動作です。Layer 1 の判定はブラウザで行われるので、返されたページを開いて確認してください。</li>
      <li><strong><code>gh</code> を使うツールが失敗する。</strong> <a href="https://cli.github.com">GitHub CLI</a> をインストールして、<code>gh auth login</code> を実行してください。</li>
    </ul>
    <p>解決しない場合は、クライアント、OS、失敗した手順を書いて <a href="https://github.com/aletheia-works/vivarium/issues/new/choose">Issue を開いて</a>ください。</p>
  </Section>
