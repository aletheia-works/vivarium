  <PageHero
    eyebrow="// GUIDE · 用語集"
    title="Vivarium で使う用語。"
    sub="このサイトでの各用語の意味です。"
  />

  <Section
    eyebrow="// 基本"
    heading="多くのページで見かける用語。"
  >
    <dl className="v-glossary">
      <dt id="recipe"><strong>レシピ</strong></dt>
      <dd>
        1つのバグを再現する1つの項目です。すべてのレシピの集まりをカタログと呼びます。
      </dd>

      <dt id="slug"><strong>slug</strong></dt>
      <dd>
        <code>pandas-56679</code> や <code>bash-local-shadows-exit</code> のような、レシピの識別子です。ツールはこれでレシピを指定します。
      </dd>

      <dt id="layer"><strong>レイヤー</strong></dt>
      <dd>
        レシピが動く場所です。Layer 1 は WebAssembly でブラウザ内、Layer 2 は手元の Docker で動きます。Layer 3 はプルリクエストのアプリケーション全体のライブプレビューで、招待された人だけが開けます。詳しくは<a href="/vivarium/ja/architecture">仕組み</a>を参照してください。
      </dd>

      <dt id="verdict"><strong>判定（verdict）</strong></dt>
      <dd>
        レシピを実行した結果です。<code>reproduced</code> はバグが起きること、<code>unreproduced</code> は起きなかったことを示します。バグがない場合のほか、バグを確かめる前に実行が失敗した場合も含むので、出力も確認してください。テストではなくバグについての言葉なので、<code>reproduced</code> はプロジェクトにとって良い結果ではありません。詳しくは<a href="/vivarium/ja/spec/contract-v1#verdict-セマンティクス">判定の意味</a>を参照してください。
      </dd>

      <dt id="evidence"><strong>エビデンス</strong></dt>
      <dd>
        判定の根拠になった出力です。標準出力、標準エラー、終了コード、実行時間などを含みます。
      </dd>
    </dl>
  </Section>

  <Section
    eyebrow="// 修正の検証"
    heading="変更を確かめるときの用語。"
  >
    <dl className="v-glossary">
      <dt id="branch-fix"><strong>ブランチ修正</strong></dt>
      <dd>
        ブランチからビルドした修正の候補です。判定が <code>reproduced</code> から <code>unreproduced</code> に変われば、このバグへの修正として効いています。詳しくは<a href="/vivarium/ja/guide/compare-branch-fix">ブランチ修正を検証する</a>を参照してください。
      </dd>

      <dt id="consumer-workflow"><strong>コンシューマワークフロー</strong></dt>
      <dd>
        自分のリポジトリの CI から Layer 2 のレシピを実行する、再利用可能な GitHub Actions ワークフローです。詳しくは<a href="/vivarium/ja/spec/consumer-workflow">コンシューマワークフロー</a>を参照してください。
      </dd>
    </dl>
  </Section>

  <Section
    eyebrow="// ツール向け"
    heading="ツールが読む形式。"
  >
    <dl className="v-glossary">
      <dt id="contract"><strong>コントラクト</strong></dt>
      <dd>
        すべてのレシピの判定の報告方法です。ツールはどのレシピも同じように読めます。詳しくは <a href="/vivarium/ja/spec/contract-v1">Contract v1</a> を参照してください。
      </dd>

      <dt id="recipes-index"><strong>レシピインデックス</strong></dt>
      <dd>
        カタログをデータにしたもので、<a href="https://aletheia-works.github.io/vivarium/api/recipes.json"><code>/api/recipes.json</code></a> にあります。詳しくは <a href="/vivarium/ja/spec/recipes-index-v1">Recipes index v1</a> を参照してください。
      </dd>
    </dl>
  </Section>
</Page>
