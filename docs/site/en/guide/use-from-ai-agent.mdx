  <Section
    eyebrow="// 3 · TOOLS"
    heading="What the server provides."
  >
    <h3>Find and read reproductions</h3>
    <ul>
      <li><strong><code>list_recipes(layer?, project?, q?)</code></strong>: lists reproductions, optionally filtered by layer (1, 2 or 3), project, or text in the slug, project or title.</li>
      <li><strong><code>get_recipe(slug)</code></strong>: returns one reproduction's details and links.</li>
      <li><strong><code>lookup_verdict(slug)</code></strong>: returns the saved verdict for Layer 2, the page to open for Layer 1 (its verdict is computed in the browser), or the preview link for Layer 3.</li>
      <li><strong><code>match_error(text, limit?)</code></strong>: ranks reproductions against an error message or stack trace, using token overlap, synonyms and small typo tolerance. It gives the same ranking as the <a href="/vivarium/repro/match">error matcher</a> page. No LLM is involved.</li>
      <li><strong><code>search_upstream_issues(project?, repo?, query?, ...)</code></strong>: searches a project's GitHub issues for bugs worth reproducing. Needs an authenticated <a href="https://cli.github.com"><code>gh</code></a>.</li>
    </ul>

    <h3>Verify a fix</h3>
    <ul>
      <li><strong><code>verify_branch_fix(slug, fix_url?, fix_source?)</code></strong>: for Layer 2, returns the workflow command and comparison link. Dispatching the workflow needs write access to the Vivarium repository. Other layers currently return an error. See <a href="/vivarium/guide/compare-branch-fix">Verify a branch fix</a>.</li>
      <li><strong><code>verify_and_report_fix(slug, ...)</code></strong>: works out the next verification step and, unless <code>auto_execute</code> is <code>false</code>, runs it. Needs a Vivarium checkout and <code>gh</code>.</li>
      <li><strong><code>create_fork_pr(slug, current_state, pr_title, ...)</code></strong>: opens a draft pull request from your pushed fork branch. By default, <code>dry_run</code> only returns the command. Needs <code>gh</code> for a real run.</li>
    </ul>

    <h3>Add to the catalogue</h3>
    <ul>
      <li><strong><code>prepare_new_recipe(project, issue, title, ...)</code></strong>: returns the commands and files for a new reproduction.</li>
      <li><strong><code>prepare_fix_candidate(slug, fork_url, branch, ...)</code></strong>: returns the files and commands to run a fork's fix beside the released build on a Layer 1 page.</li>
    </ul>
  </Section>

  <Section
    eyebrow="// 4 · TROUBLESHOOTING"
    heading="If something looks wrong."
  >
    <ul>
      <li><strong>A new reproduction is missing.</strong> The server caches the catalogue for five minutes and uses a bundled copy when it is offline. Restart the server to fetch it again.</li>
      <li><strong>A Layer 1 verdict has no result.</strong> This is expected. Layer 1 verdicts are computed in the browser, so open the returned page to see the result.</li>
      <li><strong>A <code>gh</code> tool fails.</strong> Install the <a href="https://cli.github.com">GitHub CLI</a> and run <code>gh auth login</code>.</li>
    </ul>
    <p>Still stuck? <a href="https://github.com/aletheia-works/vivarium/issues/new/choose">Open an issue</a> with your client, operating system and the step that failed.</p>
